# SVG Composer — правила проекта

Веб-сервис: собирает векторные композиции из готовых объектов (библиотека в Figma) и
экспортирует в SVG. Подробное ТЗ — в BRIEF.md. Источник истины по объектам, цветам и
правилам — файл Figma (через Figma MCP), а не память и не догадки.

## Предметные правила (нарушать нельзя)
- Объекты только копируются. Не перерисовывать, не менять элементы внутри объекта.
- Пропорции объектов друг относительно друга не менять. Масштабируется только вся
  композиция целиком одним коэффициентом.
- Объект существует в двух видах (главный цветной / фоновый монохромный) и двух размерах
  (S, L). При выборе размера подгружаются элементы этого размера.
- Цветовые схемы и их роли цветов — данные (JSON), не код. Сейчас 3 схемы, будет больше.
- Цвета фона можно использовать в объектах; цвета объектов в фонах — нельзя.
- Экспорт — валидный SVG: векторный, редактируемый, без <image> и растеризации.
- Пресеты раскладки: «Собранно», «Со смещением», «Под заголовок».
- Форматы холста: 1000×1000, 1200×630, 800×1200.
- Slug-имена объектов: lamp, headphones, phone, book, puzzle, pen и т. д. (по образцу
  слоёв в кадрах «SVG-drop»).

## Данные об объектах
- Ничего не выдумывать: имена, цвета и размеры брать из файла Figma. Если данных нет —
  сказать об этом.
- Скрытые слои (hidden) в Figma не экспортировать.
- Каталог объектов — manifest.json (id, русское имя, slug, тип, размер, теги/синонимы, bbox,
  роли цветов).

## LLM (OpenRouter)
- Вызов только с сервера. Ключ только в переменных окружения, в репозиторий не попадает;
  в репозитории есть .env.example.
- Бесплатные модели (`:free`) нестабильны и лимитированы: использовать массив запасных
  моделей, кэш, таймаут и запасной режим без LLM (поиск по ключевым словам и синонимам).
- Ответ модели — строгий JSON; валидировать: допустимы только id из каталога.

## Стиль работы
- Сначала короткий план (PLAN.md), затем выполнять без лишних остановок.
- Мелкие осмысленные коммиты.
- Не добавлять функции сверх ТЗ: важнее рабочий результат, чем объём.
- Тяжёлое чтение Figma (большие страницы) делегировать subagent figma-extractor,
  проверку в браузере — subagent qa-verifier.
- Принятые допущения фиксировать в README в разделе «Допущения».
