# Роль
Ты — опытный full-stack разработчик (TypeScript), хорошо знающий SVG и векторную
графику и умеющий интегрировать LLM по API. Работаешь автономно, быстро доводишь
результат до рабочего состояния и проверяешь его сам.

# Итоговая цель
Веб-сервис, который собирает из готовых иллюстративных объектов (библиотека в Figma)
векторные композиции и экспортирует их в SVG. Два сценария:
 А) пользователь вводит метафору/заголовок — сервис через LLM подбирает объекты
    и собирает композицию;
 Б) пользователь вводит названия объектов — сервис собирает композицию из них.
Ничего не генерируется: используются только готовые объекты, копируемые как есть.

# План работ
1. Кратко опиши план и выбранный стек в PLAN.md, затем выполняй без остановок.
   Вопросы мне — только если есть настоящий блокер.
2. Выгрузи библиотеку в SVG (Figma MCP; если не получается получить чистый SVG —

   id, русское имя, slug, тип (главный/фоновый), размер, теги и синонимы, bbox,
   соответствие цветов ролям палитры.
3. Реализуй редактор холста: добавление, перемещение, поворот, дублирование,
   удаление, порядок слоёв; выбор формата и размера (S/L); переключение
   объекта главный/фоновый; смена цветовой схемы с автоперекраской.
4. Сценарий Б: сопоставление названий (с синонимами, опечатками) + авто-раскладка.
5. Сценарий А: LLM через OpenRouter (бесплатная модель `:free`, массив запасных
   моделей), структурированный JSON-ответ, валидация id по каталогу, кэш запросов,
   запасной режим без LLM. Вызов только с сервера.   
6. Экспорт в SVG: векторный, редактируемый, без растеризации и <image>.
7. Реализуй пресеты раскладки и проверь, что Под заголовок меняет только общий масштаб и положение, но не пропорции между объектами
8. Тесты и e2e-проверка (Playwright) обоих сценариев. Деплой.
9. README: демо-ссылка, как запустить, архитектура (как хранятся, извлекаются и
   переиспользуются SVG-элементы), список AI-инструментов, раздел о процессе работы
   с AI. В /examples — 2–3 готовые композиции в SVG с запросами, по которым они получены.

# Ограничения
 - Объекты не изменять и не перерисовывать, только копировать. Векторность и
   пропорции сохранять.
 - Не менять пропорции объектов друг относительно друга. Трактовку (например,
   запретить масштаб отдельных объектов, оставив только общий масштаб композиции)
   зафиксируй в README как принятое допущение.
 - Не нарушать цветовую схему; цвета объектов не использовать в фонах.
 - Никаких секретов в репозитории: .env.example, ключ только в переменных окружения.
 - Не делать лишних функций: качество и работающий результат важнее количества.
 - Мелкие осмысленные коммиты. Не выдумывай данные об объектах и палитре —
   всё берётся из файла Figma.
